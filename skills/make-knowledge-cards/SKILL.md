# Make Knowledge Cards

把用户粘贴的文章或本地 `.md`/`.txt` 文件，提炼成 5~8 张可直接用于学习与复习的知识卡片。每张卡片聚焦一个知识点，便于记忆、测试和自我检查。

## 输入与输出

**输入（三选一）**
- 直接在对话中粘贴的文章正文（纯文本）
- 本地 `.md` 文件内容
- 本地 `.txt` 文件内容

**输出**
- 5~8 张知识卡片，每张卡片固定包含四个字段：
  1. **标题** —— 一句话概括本卡知识点，简洁有力
  2. **核心知识** —— 用 1~3 条要点讲清楚该知识点的骨架，只放原文出现过的内容
  3. **简明解释** —— 用日常语言把核心知识展开说明，帮助理解
  4. **例子或自测问题** —— 提供一个贴切例子，或出一道能检验是否掌握的自测问题（二选一即可，可同时给出）

## 工作流程

按以下顺序处理，不要跳步：

### 第 1 步：通读全文并理解
通读整篇文章，把握主旨、段落结构与论述脉络，识别文章真正在讲什么。

### 第 2 步：提炼候选知识点
把文章拆解为若干个独立的知识点。识别标准：
- 能独立成说、独立理解的最小知识单元
- 对理解文章主题必不可少，删除后会影响读者抓住要领
- 区别于背景铺垫、客套话、重复句、离题内容

### 第 3 步：去重与筛选
- **删除重复内容**：同一知识以不同措辞重复出现时，只保留一次，合并进一张卡
- **删除非知识内容**：例外的八卦、情绪化表达、与主题无关的段落不进入卡片
- **只保留真正重要**：宁可少而精，不追求把每个细节都做成卡

### 第 4 步：合并为一个知识点一张卡
如果多个候选知识同属一个主题、合并后仍是一个清晰的知识点，就合并成一张卡；反之若拆开能各成一张，就保持拆分。**严格保证"一张卡片只讲一个知识点"。**

### 第 5 步：控制卡片数量
- 目标 **5~8 张**。
- **信息不足时不要强行凑数量**：如果原文只能提炼出 3 个扎实的知识点，就输出 3 张卡，不要为凑数编造或注水。
- 只有当原文内容确实丰富、有足够多的独立知识点时，才输出接近 8 张。
- **叙事/文学/情感类文本的边界**：如果原文是散文、小说、随笔等以叙事或抒情为主、几乎不含可拆解的事实性知识点，不要硬把它"知识点化"。此时如实向用户说明：该文本偏叙事/文学，缺乏可提炼的知识点，不适合本工具；最多在有明确事实依据的前提下提炼 1~2 张"文中事实要点"卡，否则不产出卡片。

### 第 6 步：逐卡撰写四个字段
严格按"标题 / 核心知识 / 简明解释 / 例子或自测问题"填充。写完后回读一遍，确认每个字段都只来自原文，没有添加原文没有的信息。

## 硬性约束（必须遵守）

1. **不能编造**：卡片里的任何事实、数字、结论、例子都必须能在原文中找到依据。原文没有的信息一律不写。若原文某处信息不完整（如缺数据、缺步骤），在卡片中如实标注"原文未提供"，不要自行补全。
2. **一张卡片一个知识点**：不允许把多个不相干的知识塞进同一张卡。
3. **删除重复内容**：合并同一知识点的重复表述，卡片之间不得出现雷同。
4. **信息不足不凑数**：宁可输出少于 5 张，也不为凑到 5 张而编造或注水。
5. **尊重原文范围**：只做"提炼与整理"，不做扩展、改写立场或补充外部知识。不要加原文没有的例子来"帮忙"——例子若原文没有，就用"自测问题"代替。
6. **叙事文本不硬转**：散文、小说、随笔等以叙事抒情为主、缺少事实性知识点的文本，如实告知不适合，不强行产出"氛围卡"。

## 不支持的输入（明确拒绝并说明原因）

- **网页抓取**：不访问、不抓取任何 URL，只处理用户提供的文本。
- **PDF / Word / 图片等二进制文档**：只处理纯文本，其他格式请用户先转成文本或直接粘贴内容。
- **Anki 导入**：不生成 .apkg 等 Anki 专用格式。
- **图形界面**：不做 GUI 输出，卡片以 Markdown 文本形式直接呈现。

## 输出格式

用 Markdown 分节呈现每张卡片。示例如下：

```
## 卡片 1｜标题
**核心知识**
- 要点一
- 要点二
**简明解释**
日常语言展开说明。
**例子或自测问题**
- 例子：……（或）
- 自测：……
```

输出末尾可加一行简短说明，注明实际生成的卡片数量，以及原文中因信息不足而未展开的内容（如有）。
